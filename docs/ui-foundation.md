# UI visual foundation (flat retro-poster kawaii)

Small visual slice pulled ahead of the Milestone 1 quest work. It follows the "retro travel-poster kawaii" direction in `plan.md` (style A: flat shapes, limited palette, a little soft depth). Milestone 5 turned this into the full visual pass - illustrated map art, aircraft silhouettes, the time-of-day palette, the mascot and onboarding, and Framer Motion are all done, below.

## In scope

- **Design tokens** as CSS variables in `frontend/src/styles/base.css` (`--paper`, `--paper-light`, `--ink`, `--sea`, `--land`, `--accent`, `--on-accent`, `--highlight`, `--mint`, the ink at four strengths `--ink-6/20/25/35` for shadows and faint lines, plus font variables). The stylesheet is split by feature in `frontend/src/styles/`, listed in order in `index.css`. Since Milestone 5, `--sea`/`--land` are overridden per time-of-day (see below); the rest stay fixed, so a later region/weather shift only needs to add more overrides in the same style.
- **Fonts**: Fredoka (display) and Nunito (body), self-hosted through `@fontsource` packages.
- **Aircraft markers**: SVG plane silhouette (`PlaneIcon.tsx`) rotated by `heading`; the selected plane gets a mustard ring. Since Milestone 5, the shape itself varies by aircraft family (below), not one generic silhouette for every flight.
- **Illustrated map** (Milestone 5): Natural Earth coastlines (`WorldLand.tsx`, `worldLandData.ts`, generated by `scripts/build-land.mjs`, unchanged since Milestone 2) rendered with poster-style depth instead of a flat fill - a light-to-dark gradient (`#landFill`, defined in `WorldLand.tsx`'s `<defs>`, built from `--land` with `color-mix()` so it follows the time-of-day palette) lit from the north across the whole map, plus a soft zoom-compensated drop shadow lifting land off the sea. The graticule (`.grid`, every 30 degrees) is a faint ink-toned dotted line rather than stark white dashes, reading as a parchment ruling instead of a technical grid. The sea is a `.map`-level CSS texture - two faint diagonal `repeating-linear-gradient` line sets (gentle current lines) over the base `--sea` colour - living outside `.map-world` (so it doesn't pan/zoom; the open ocean has no geography to align to).
- **Country borders and name labels** (Milestone 5, requested after the first pass above, `CountryBorders.tsx`/`countryData.ts`, generated by `scripts/build-countries.mjs` from the same Natural Earth 1:110m family as the coastlines): a thin, translucent ink border per country (`.border`, coinciding with the coastline where a country meets the sea, same as any real political map) plus a name label per country, using Natural Earth's own curated `LABEL_X`/`LABEL_Y` anchor and `LABELRANK` (2 = major, 7 = minor) rather than a computed centroid. Two things worth remembering if this is touched again:
  - **Labels are a constant screen size** (`.country-label`'s `scale(1/--zoom)`, like the plane icons), *not* scaled with the map like the land or borders. This was a deliberate correction: an earlier version scaled label font size with the map too, which seemed elegant (bigger countries automatically read bigger) but actually broke decluttering - since the text and the geographic gap between two countries' anchors would then grow by the exact same zoom factor, two colliding labels could never resolve by zooming in. With a constant screen size, zooming in genuinely grows the pixel gap relative to the fixed-size text, so a crowded pair at low zoom can separate once zoomed in.
  - **Real collision avoidance, not a fixed zoom threshold.** `CountryBorders`'s `useMemo` greedily places labels sorted by rank (biggest/most-important first), skipping any whose estimated screen-space bounding box (from a rough `name.length * fontPx * 0.62` width estimate, no DOM measurement) collides with an already-placed one. This needs the map box's actual rendered width (`mapWidthPx`, tracked in `FlightMap.tsx` via a `ResizeObserver`, guarded for jsdom's tests where it doesn't exist), since fractional pan/zoom state alone isn't enough to compute real pixel gaps. This replaced an initial, simpler rank-based "show above this zoom" scheme, which crowded badly over Western Europe by default (several rank-2 countries - the UK, Germany, France, Belgium, Spain - sit close together there) since it had no way to know two specific labels were about to overlap.
- **Aircraft silhouettes by shape** (Milestone 5, extended after the MVP; `aircraftSilhouette.ts`): 10 shapes, classified from the ICAO type code by its category and engine count in the type catalog (`shared-lib/aircraftTypes.ts`), so the quests and the art agree. Airliners, in coral: narrow-body twin-jet (also the fallback for an unrecognized code), regional jet, wide-body twin-jet, quad-engine/double-deck, turboprop, all from the same nose/wing/tail recipe (mirrored left/right) with engine circles on the wide-body, quad and turboprop; and the business jet (swept, two engines on the rear fuselage, T-tail). General aviation, in mint and drawn smaller inside the same 24-unit box (the tap area stays 28 px): light aircraft (straight wing, nose propeller; high and low wing look alike from above), light twin (an engine on each wing, `engines: 2`), helicopter (round cabin, tail boom and tail rotor, and a main rotor of thin ink lines that turns once every 1.2 s and stands still under reduced motion), glider (long thin wings, T-tail). A single-engine turboprop (`engines: 1`: Caravan, PC-12, TBM, Meridian) uses the light-aircraft shape, since from above it is one nose propeller, not two wing discs. Mint, chosen over all-coral and all-ink on a preview sheet: the small traffic stands apart at a glance without a colour per category, and the outline keeps the shapes readable; it holds at the dusk and night palettes, which only change the sea and land. Skids on the helicopter and a canopy on the glider were tried and dropped: invisible at 28 px. Not one drawing per code: e.g. A319/A320/A321 barely differ externally, so they share a shape.
- **Time-of-day map palette** (Milestone 5): `.map[data-map-time="dawn|day|dusk|night"]` in `styles/map.css` overrides `--sea`/`--land` only (card/button/journal tokens are untouched). `FlightMap.tsx` sets the attribute from `timeOfDay(longitude, now)` (`attributes.ts`, unchanged, already used by quests/facts), fed the *current viewport's* centre longitude - `centreOf` (newly exported from `panzoom.ts`) plus a new `unprojectLongitude` (`projection.ts`). So it's the solar time where the view is currently centred, not the viewer's device clock: panning to another part of the world can shift the palette. Recomputed every render, which already happens on pan/zoom and the 5 s flight poll, so no new timer was added. The colour change itself eases over 0.9s (`transition: --sea, --land`) rather than snapping, which needs `--sea`/`--land` registered via `@property` as `<color>` - an untyped custom property can only swap values instantly, but a registered one lets the browser interpolate through intermediate colours, and everything that reads it (the sea's `background`, the land gradient's `color-mix()` stops) recomputes smoothly for free, with no extra `transition` needed on any of those consumers. Skipped under `prefers-reduced-motion`. A region palette shift is still deferred; a local weather tint was tried in Milestone 6 and dropped (see "Weather icons" below).
- **Route and journey replay** (Milestone 2):
  - **Route line.** The selected flight's route is an ink line: solid (3px) where it has flown, dashed and slightly faded (2px) ahead.
  - **Airports.** Each end has a small paper dot with the IATA code in a mustard chip, like the card chips.
  - **Ghost plane.** The replay ghost is the same plane icon at 60% opacity, and it leaves a solid trail. Both fade out (`fade-out` keyframes) when it lands.
  - **Journey button.** A secondary paper button with an ink outline and flat shadow, next to the coral Catch.
  - **Zoom.** Like the land, line widths are divided by `--zoom` so they look the same at any zoom. The route SVG is named `.route-lines` because `.route` is the card's route text.
  - **Through the plane** (Milestone 7). A live plane is rarely on the great circle, so the line is the great circle bent sideways (`curveThrough` in `geo.ts`) by exactly the plane's offset at the plane and by nothing at the airports, with a smooth ease so there is no kink. The solid and dashed parts meet exactly at the plane, and the replay ghost and trail follow the same curve. A plane that is on the arc (the mock's) leaves it unchanged. The line only claims "origin, through here, to destination", not a flown track, which we don't have.
  - **Readability over dense traffic** (Milestone 7; seen with a live feed). Each route line has a wider paper-coloured outline (`.route-casing`, which needs a selector as strong as `.route-lines polyline`, or the stroke stays ink). Stacking: other planes (`z-index: 1`), then the route and its airports (2), then the selected plane and the ghost (3). Focus mode (`data-focus` on the map, set in `FlightMap.tsx`): with a flight selected the other planes' icons dim to 30%; during its replay they fade to nothing (fully: even a faint drop shadow left smudges) and ignore clicks, and the featured and target rings go too. The dimming is on `.plane-icon`, not `.plane`, which has its own fade-in animation. Planes also shrink with zoom: full size at zoom 4 and above, down to 60% at zoom 2.4 and below, because 28 px planes pile into a wall when the whole world is in view. Checked in Chromium with 500 extra planes and a plane pushed off its arc.
- **Map controls** (Milestone 2): +/−/reset buttons in the map's bottom-right corner, styled like small cream tickets with the ink border and a flat shadow. The map shows a grab cursor.
- **Featured flights** (Milestone 3): a dashed paper-coloured ring that gently pulses (`featured-pulse`, off under reduced motion) around 2–3 planes picked for the session. The selected plane's solid mustard ring replaces it, since the selected rule comes later in the CSS. The ring is a `::after` pseudo-element, so it may use `transform`.
- **Card**: ticket look with callsign, aircraft-type and altitude chips, the fact in a speech-bubble block and a coral Catch button. Since Milestone 4 it's a passport page (below). Since Milestone 5 its entrance is a Framer Motion spring (below), not the CSS `pop` keyframes.
- **Motion**: CSS-only pop on selection and most appearance/disappearance, disabled under `prefers-reduced-motion`. Since Milestone 5, the card, the stamp and the badge popup use Framer Motion instead (below) - everything else (journal entries, the featured-ring pulse, map/route animations) is still plain CSS.
- **Quest strip** (added with Milestone 1): a slim ticket above the map, using the card's paper, border and shadow, with an inverted "QUEST" label. On completion, a coral rubber stamp ("Done!", `Stamp.tsx`, below) lands, and the mascot appears with the concept fact (Milestone 5, below) under a dashed tear line.
- **Journal and caught state** (added with Milestone 1):
  - **Journal entries** are small ink stamps (since Milestone 4, see below), stacked below the map, newest first (since Milestone 4, inside the Collection screen). They pop in with the shared `pop` animation (plain CSS, not converted to Framer Motion - see the "card, stamp and popup" scoping note below).
  - **"Caught today ✓"** replaces the Catch button on the card and reuses `Stamp.tsx`, so "caught" and "quest done" share one stamp look — the same for every flight, and immediate: Catch turns the button into the stamp and the card stays open (it used to close right away, so the stamp was never seen; changed 2026-10-09). The card closes by tapping the plane or the map.
- **Stamp** (`Stamp.tsx`, Milestone 5): the shared rubber-stamp look (coral, double border, tilted -8deg) for "Done!" and "Caught today ✓", replacing the old CSS `stamp` keyframes with a Framer Motion spring (starts big and faded, lands at the tilt). Under `prefers-reduced-motion` it renders a plain `<span className="stamp stamp-still">` instead - no Framer Motion at all, not just a shorter transition (`.stamp-still` supplies the resting tilt that would otherwise come from the animate prop). `.stamp` itself is still `inline-block`, because a transform (Framer Motion's or `.stamp-still`'s) is ignored on a plain inline element.
- **Passport card** (Milestone 4): the flight card is a passport page — `.passport-page`'s faint ruled-line background, a `.passport-strip` header band bled to the card's edges ("WINGDEX · FLIGHT PASSPORT"), the existing chips plus a new HEADING chip (rounded to a whole degree), and the fact reframed as "Did you know? ...".
- **Entry stamp** (Milestone 4, `EntryStamp.tsx`): a small static ink stamp, `.entry-stamp`, showing the destination IATA code (like a real immigration entry stamp, not a route) with a callsign fallback when there's no known destination, plus the date and callsign in smaller print. It's Journal-only — an early version also played it as a landing catch-moment animation with a delayed card close, but that was simplified away after review in favour of one uniform, immediate catch reaction for every flight (above) and the stamp being purely how a Journal entry looks.
- **Collection screen** (Milestone 4; redone with the Dex, see "Collection, Dex and badges" below): Journal, Badges and Facts tabs behind a header toggle button (`.collection-btn`, `.app-header`).
  - **Journal tab**: a wrapping row of entry stamps (`.journal ul` is `display: flex; flex-wrap: wrap`) — "a page of stamps"; since the Dex, tapping one opens the catch's details.
  - A badge unlock shows `.badge-popup`, a fixed toast in the map's corner, deliberately not reusing `.stamp`/`.entry-stamp` — badges are a different kind of reward from a catch. Since Milestone 5 it's a Framer Motion `motion.div` wrapped in `<AnimatePresence>` (`App.tsx`), which fixed a real gap - the old CSS version had no exit animation at all and just vanished on dismiss. Under `prefers-reduced-motion` it's a plain `<div>` instead (no Framer Motion, no `AnimatePresence` tracking needed), unmounting immediately like before Milestone 5.
- **Mascot** (`Mascot.tsx`, Milestone 5): a hand-drawn chibi cat pilot (goggles, same chunky ink-outline style as the plane icons), cropped like a passport-photo bust to tie into the card's own theme. No idle animation, only the entrance/exit transitions its callers (Onboarding, the quest strip) apply. An optional `mood` prop swaps the face: `idle` (default, "w" mouth), `talk` (open mouth) and `cheer` (happy `^ ^` eyes + open mouth).
- **Onboarding** (Milestone 5, `Onboarding.tsx`/`useOnboarding.ts`): runs once ever per device (`onboardingSeen.ts`, same persisted-flag pattern as `badgesSeen.ts`). Deliberately non-blocking - the mascot (`.onboarding`, docked fixed bottom-left; `BadgePopup` is bottom-right so they never collide) stays on screen for the whole flow and "says" each step in a speech bubble beside it (`.onboarding-bubble`, CSS tail), typed out character by character (instant under reduced motion) with the mascot in `talk` mood while typing and `cheer` on the last step. A state machine (`greeting` -> `catch` -> `done` -> gone) drives it: the greeting is dismissed with a "Got it!" button, then a prompt highlights one real flight near the default view (`onboardingTarget.ts`) but completes on *any* catch, not strictly that one, and a "Nice catch! Peek at your Collection" line (5 s) auto-dismisses like the badge popup, while the Collection button pulses mustard (`.collection-btn.nudge`) as the pointer. A "×" always lets it be skipped early. Built with Framer Motion from the start (an `AnimatePresence`-wrapped spring, or plain `<div>`s under `prefers-reduced-motion`).
  - **Highlight**: the target plane gets `.plane.target` (`FlightMap`'s `targetId` prop) - a thick mustard ring with an ink outline and a ripple - distinct from the daily featured ring. The target is pinned in `useOnboarding` once picked (re-picked only if it leaves the feed), since re-picking "nearest to the centre" every render made the ring hop between moving planes.
  - **Bug found while building this**: the bubble's fixed position could sit over the flight card's own Catch/journey buttons on a short viewport, actually blocking clicks. Fixed by turning the bubble into a click-through hint while a card is open (`cardOpen` prop; `.onboarding-bubble.hint` has `pointer-events: none`, a short "Hit Catch" line and no buttons), plus bottom padding on `main` (`.has-onboarding`) so the card can scroll clear of the mascot.
  - **Bug found while polishing**: the highlight was invisible - the ring was a 2px dashed `--paper` circle, nearly the same colour as the land. Featured rings now use `--ink`, and the onboarding target has its own bold ring.
- **Quest-completion mascot** (Milestone 5): the mascot appears next to the quest's concept fact (`.quest-fact-row` in `QuestBanner.tsx`) once the day's quest completes - a once-a-day "bigger celebration" moment, not the always-visible quest banner itself (which stays mascot-free) or the per-catch fact on every card (which would make the mascot repetitive).

## Collection, Dex and badges (2026-10-19)

Reworked over four rounds of screenshots with the user; `docs/history.md` has the versions that were dropped and why. The Collection now has four tabs: Journal, Dex, Badges and Facts.

- **One rule for shapes.** Tiles, cards, the Dex switch and the filter chips are rounded rectangles (8-12 px), like the flight card; pills (fully round) are kept for small counters and the header button. Pill-shaped switches and folder-shaped tabs were tried and found jarring next to the tiles.
- **Tabs** (`.collection-tabs`, `.tab`): plain words on a faint ruled line, the open one in full ink with a 4 px coral underline. Lighter than everything below them, so they read as the page's top level and don't compete with the Dex's switch and chips.
- **Three levels in the Dex**, each lighter than the one above: a segmented switch (`.dex-switch`: one bordered bar split in three, the open part filled ink), then filter chips (`.dex-chip`: faint outline, the active one mustard) with their own counts ("Wide-body 4/9"), then the tiles. One category or airline kind is shown at a time, so the page stays short; a full list stacked every category and ran to about 4,000 px on a phone.
- **Counters** (`.pill`) sit on the right above a list: "✈️ 10" for catches and "💡 30" for facts (the noun is for screen readers), and on the Dex "🔥 4-day streak" beside "🏆 Best: 7-day streak" (a bare "Best 7" read as unclear). Each shows only once it has something to count, so a new player sees no "0-day streak". The Dex is the streak's only home: a pill on the map's quest strip was tried and taken off, as it crowded the centre of the screen for something that isn't about today. Headings like "Journal (10)" repeated the tab, and a counter on the tab itself was rejected.
- **Caught in colour, the rest as outlines.** A family tile (`.dex-tile`) shows a map silhouette in the map's coral or mint once a type of it is caught, and before that a thin solid ink outline at 35% with no fill, in a dashed-bordered tile. A filled 18% shadow was tried first and lost the engines and wings that tell a turboprop from a light aircraft; a dashed outline broke the small shapes into dots. The silhouette is the latest catch in the tile (`tileType` in `dex.ts`), so "Other light aircraft" shows the twin you caught, and before any catch the group's most common shape, not its first type (which made "Other turboprops" look like a light aircraft). Families of one shape still look alike, by design: the silhouettes are per shape, not per model. The helicopter's rotor stands still in the Collection (tiles and pop-ups): cute on the map, but the only moving icon among still ones here; a dot per type (coral when caught), or "3/23" above 8 types. Airlines show only the caught ones, then one shadow tile "+N to find" (always with the "+"); listing every unseen name made the page a wall of grey text.
- **Tail fins** (`TailFin` in `DexView.tsx`): a drawn side view of a fin (swept leading edge, short top, near-upright trailing edge) on a strip of fuselage, coral with the ICAO code in white, because the tail is where a real airline carries its livery. A trapezoid was tried first and read as nothing.
- **Flags** for the passport (`Flag.tsx`, `flag-icons`, 4x3, inside a 2 px ink border), at the fin's size so the grids match. Not emoji, which Windows draws as two letters. Stamps were tried first. Until a flag's file has loaded, its frame shows a faint fill and a small spinning ring (still under reduced motion), since the bigger files take a moment.
- **Medals** (`.medal`): 96 px paper discs with an ink rim and drop shadow (68 px on phones), icon and name only. Locked: the badge's own icon in greyscale at half opacity on a dashed rim, plus a small 🔒 on the rim, outside the greyed disc so it stays readable. Earned ones carry no label. The yellow disc of the first version was dropped as unnecessary.
- **Pop-ups** (`DetailDialog.tsx`, `.detail-dialog`): for a badge, an aircraft family and a Journal catch. A centred paper card over a 45% ink backdrop, springing in with the shared `pop` (off under reduced motion), closed with a coral OK like the Catch button, Escape or the backdrop. A native `<dialog>` with `showModal()`, so the browser traps focus. A bottom toast was tried and dropped: the user wanted something that asks to be acknowledged, unlike the unlock popup. Lists in it are left-aligned with a column for the ticks (`.detail-dialog-mark`), so caught and uncaught names start at the same place. It grows to the screen height and only scrolls when it truly can't fit, since a scrolled-down pop-up hid its own icon on a phone.
- **A catch's pop-up** (`CatchDetails.tsx`): the plane's silhouette and callsign, the radio callsign in italics, then boarding-pass rows like the card's (`.catch-rows`: a small-caps label left, the value right, dotted rules) for the time, route, aircraft, airline, altitude, speed and weather, each only when known. The fact and quest were in it at first and taken out to keep it short and about the flight: they have the Facts tab and the quest strip.
- **Facts** are grouped under small headings with a count (Aircraft, Airlines, Flying, Weather, Around the world, Other), still in the mint speech bubbles.

## Weather icons (Milestone 6)

Settles the plan's open "weather iconography" item. `WeatherLayer.tsx` draws hazard areas from `GET /weather` under the planes:

- **Stickers.** One round sticker per icon (`.weather-icon`): ink outline, a one-offset drop shadow like the planes, and a glyph from `HazardIcon.tsx` on a palette-token background (thunderstorm mustard, turbulence mint, icing pale sea, volcanic ash accent red, cyclone sea, mountain wave pale peach). Glyphs are chunky ink-outlined shapes in the same style as the plane silhouettes: cloud and bolt, three waves, a mountain under a wave line, snowflake, volcano with plume, pinwheel. Constant screen size, like planes (`scale(1 / var(--zoom))`).
- **Several icons per area, by size and zoom** (`weatherIcons.ts`). One icon when the area is small on screen, up to `MAX_ICONS` (4) as it grows. Positions come from a lattice over the polygon's bounds, keeping only points inside the polygon (reusing `inRing`), so an icon never sits outside a concave hazard. The order is fixed (most central first, then farthest-apart), so zooming in only adds icons and never moves the existing ones.
- **Shape on click only.** An always-on fill for every area would compete with the land, borders and planes. Clicking an icon draws that area's dashed outline with a faint ink wash and a chip label (hazard, region, altitude band; live data adds severity and a volcano or storm name, e.g. "Tropical cyclone (Koguma)"). The label sits above the planes (`z-index: 4`), because in busy skies it was unreadable under them. Clicking again, a plane or the map background clears it. Selecting a weather area deselects the flight and the other way round.
- **Weather switch.** A ☁ button at the top of the map controls hides or shows all weather (icons, outline and label), for anyone who finds the map too busy; hiding also drops any selected area. It is on by default and not remembered between visits. Planes and quests are unaffected.
- **Tried and dropped: a weather tint.** A soft, neutral grey-blue wash (SVG polygons, blurred edges, `mix-blend-mode: multiply`) over each hazard area, local rather than a global palette swap. Seen in a browser it looked like muddy smudges on the tan land, was nearly invisible over sea, and vanished at world zoom where the areas are tiny, so the icons alone carry the weather. Region and weather palette shifts stay deferred.
- **Known limits.** Planes are drawn above weather icons, so a plane can sit over an icon (seen over the Alps in the opening view); the area's other icons, or zooming in, still reach it. The cyclone and storm glyphs are the least legible at 26 px. The pixels-per-map-percent estimate behind the icon count assumes a map about 1000 px wide.

## Framer Motion (Milestone 5)

Added as a real dependency, per the plan's long-standing intent. Converted: the card's entrance, the stamp, and the badge popup (including giving it a real exit animation for the first time) - matching the plan's "springy card, stamp and popup motion" scope. Left as plain CSS: the Journal grid's pop-in, the featured-ring pulse, and every map/route animation, since those are tightly coupled to the zoom-compensated SVG math and weren't part of that scope. The new mascot/onboarding UI was built with Framer Motion from the start rather than more CSS keyframes.

Every converted component skips Framer Motion entirely under `prefers-reduced-motion` - a plain element with no `motion.*` wrapper, not just a shortened transition. Besides being the more correct accessibility behaviour, this turned out to matter for testing: Framer Motion's animations run on `requestAnimationFrame`, and under Vitest's fake timers, an exit transition (`AnimatePresence`) could fail to ever complete once several earlier tests in the same file had already driven fake-timer-based animations - some form of cross-test scheduler state leak, not a per-test timing issue (an isolated repro of the same code always passed). Advancing timers in smaller steps, or switching to real timers, didn't fix it; mocking `window.matchMedia` to report reduced motion for the specific tests exercising dismiss/auto-dismiss behaviour did, since it makes those components skip Framer Motion's machinery altogether. That mock is scoped per-test (see `App.test.tsx`'s `reducedMotion()` helper), not global, because the existing journey-replay tests specifically need `prefersReducedMotion()` to read `false` to see the real ghost animation.

## Notes

- The land polygons are simplified Natural Earth coastlines. Milestone 5 kept them as the geography and only changed how they're rendered (the gradient fill and shadow, above) - not a hand-drawn replacement. An earlier version of this note said the polygons themselves were throwaway and would be replaced; that turned out not to be the right scope once Milestone 5 actually started (redrawing world geography by hand isn't a reasonable ask for a solo portfolio project, and the existing polygons are already geographically accurate), so this note corrects it.
